# MDF Progressive Documentation — Agent Entry Card

The MDF 1.9a field documentation (`docs/mdf/MDFields19a_UTF8.txt`, frozen — see
`docs/mdf/SOURCE-PROVENANCE.md`) is migrated into the progressive-read Markdown
directory `docs/mdf/ai-progressive/` (issue #1380). Those Markdown files are the
maintained source of truth; the Toolbox original is never written to.

## READ — looking up field documentation

Enter by intent:

- **You know the marker code.** Read `docs/mdf/ai-progressive/markers/{code}.md`
  — one file per `\key` entry (a multi-code entry is one file listing all codes
  in its frontmatter `marker` field; the verb-paradigm entry lives at
  `docs/mdf/ai-progressive/markers/1s.md`).
- **You are browsing or unsure of the exact code.** Read
  `docs/mdf/ai-progressive/index.md` (Level 1: every code linked, one-line
  summaries, under 2,000 tokens).
- **You are working job-framed.** Read the concern views —
  `docs/mdf/ai-progressive/concerns/structure.md`,
  `docs/mdf/ai-progressive/concerns/semantics.md`,
  `docs/mdf/ai-progressive/concerns/presentation.md`,
  `docs/mdf/ai-progressive/concerns/data-handling.md` — each links into the
  participating entries' own concern sections.
- **You need a cross-cutting discussion.** Read the topic files —
  `docs/mdf/ai-progressive/topics/hierarchy-standard.md`,
  `docs/mdf/ai-progressive/topics/hierarchy-alternate.md`,
  `docs/mdf/ai-progressive/topics/formatting-printing.md`,
  `docs/mdf/ai-progressive/topics/character-styles.md`,
  `docs/mdf/ai-progressive/topics/range-sets.md`,
  `docs/mdf/ai-progressive/topics/old-changed-markers.md`.
- **Orientation, conventions, inventory.** Read
  `docs/mdf/ai-progressive/README.md`.

Every entry file carries frontmatter (`marker`, `category`, `hierarchy_level`,
`concerns`, `cross_refs`, `tokens_estimate`), a `## Cross-references` section
whose links resolve to the referenced entries' files, and a `## Backlinks`
section listing entries that reference it. Follow links instead of re-reading
the frozen source.

## WRITE — changing MDF documentation

- The migrated Markdown is the source of truth: edit
  `docs/mdf/ai-progressive/markers/{code}.md` directly. Never edit
  `docs/mdf/MDFields19a_UTF8.txt` — it is frozen provenance.
- When editing an entry file, keep its frontmatter accurate: if the edit
  changes the entry's concerns, update `concerns` and regenerate the affected
  view under `docs/mdf/ai-progressive/concerns/` so the view's entry list stays
  equal to the frontmatter declarations; if it adds or removes a reference,
  update both `## Cross-references` here and `## Backlinks` in the target
  entry file, plus the `cross_refs` frontmatter on both sides.
- Keep the token budgets: every file under 4,000 tokens
  (ceil(bytes / 4)); `docs/mdf/ai-progressive/index.md` under 2,000.
- `docs/mdf/ai-progressive/README.md` documents the conventions — read it
  before the first edit.

## PLAN — designing against MDF fields

- Before proposing record structures or marker usage, read the marker's entry
  file under `docs/mdf/ai-progressive/markers/` and its hierarchy placement
  (`hierarchy_level` frontmatter; section boundaries are `\lx`, `\ps`/`\pn`,
  `\sn`, `\se` — see `docs/mdf/ai-progressive/topics/hierarchy-standard.md`).
- Before designing import/export or validation logic, read
  `docs/mdf/ai-progressive/concerns/data-handling.md` and the entries it lists.
- The parsed machine view used by the HTML/PDF workflow is
  `docs/mdf/build/master.json` (generated by `scripts/convert_mdf_master.py`,
  validated by `test/test_mdf_cf_pairs.py` and
  `test/test_mdf_converter_sc13_and_census.py`); consult it when a task needs
  structured fields rather than prose.

## VERIFY — checking MDF-related work

- Marker facts asserted in tests or docs must match the entry file under
  `docs/mdf/ai-progressive/markers/` — resolve the marker via
  `docs/mdf/ai-progressive/index.md` first.
- Hierarchy/section-boundary claims trace to
  `docs/mdf/ai-progressive/topics/hierarchy-standard.md` or the
  `Sections_in_a_Lexical_Entry` entry.
- Cross-reference claims trace bidirectionally: the referencing entry's
  `## Cross-references` and the target's `## Backlinks` must agree.
- Concern-view consistency: an entry listed in a concern view must declare
  that concern in its frontmatter, and its file must carry the matching
  `##` section.
