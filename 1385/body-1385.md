## Problem

The records page has no way to use the semantic gloss search the db/embed specs deliver: the mode radio exposes only Headword/Gloss/Lexeme/FTS, there is no similarity-threshold control, no similarity-score display, and no handling for semantic-search degraded-state payloads. Linguists need the end-user surface of semantic search on the app's primary search page.

## Scope

- Two new mode radio entries (Semantic Gloss, Semantic All) with developer-approved captions in the existing records-page radio; existing entries/captions/keys untouched.
- A per-user similarity-threshold preference control — slider + numeric input, two-way coupled, invalid edit rejected with snap-back — persisted via PreferenceService (`records`/`semantic_threshold`, default `0.80`).
- Similarity-score badges/captions on semantic-mode result rows in descending order; exact-match modes render unchanged.
- Rank-once pagination: page navigation slices the service's full ranked list; no re-rank or re-invocation on page change.
- Clean empty-state rendering for every seam status (`empty_query`, `no_embeddings`, `stale_model`, zero-below-threshold), with stale/no-embeddings messages naming the admin backfill remedy.

**Out of scope (owned by the db/embed spec #36):** embedding model artifacts, pgvector schema/migrations, search service internals, admin backfill button, calibration, DDL. Threshold storage layer (`preference_service.py`) is consumed as-is in both specs.

## Approach

Bind the records page to the `search_semantic` seam contract (v1 field list: `results: list[(record_id, score)]`, `status` enum, `message`) — the UI layer imports nothing below the service seam. Mode selection dispatches through the existing `search_records` entry with the additively-widened SearchMode values, so existing modes' behavior is regression-safe. The threshold control follows the developer-decided widget contract (two-way coupled slider/numeric, invalid-edit snap-back) and persists per user via the existing PreferenceService. Pagination follows rank-once slice semantics: the service returns the full ranked list once, page navigation only slices it, so ordering can never change mid-paging. Result rendering gains one semantic branch for score display and status-keyed empty states.

## Impact

- **Risk: regression on the highest-traffic page** — SC-7's behavioral harness guards the four existing modes' results; mode keys and session-state keys preserved (`records.py` verified).
- **Risk: seam mismatch during cross-spec development** — UI binds only to the v1 contract enumerated in the analysis artifacts; any status-enum extension is a versioned contract migration. Key dependency: #36 delivers the seam first.
- **Risk: preference corruption via invalid widget input** — snap-back validation (SC-3) plus persistence round-trip verification (SC-2) on real synced data.

Call to action: review; this spec implements after #36's db/embed items 5 (seam) land.
